# Phase 2: Core kit and mechanisms

PRD: `PRD.md` §6 P2. Phase goal: the full MVP piece set (16 items in the PRD list), each generated by Blender, collision-correct, and behaving deterministically in the sim, demonstrated by one test track that uses every piece.

Inputs: kit generator scaffold (P1-T2), chunk colliders (P1-T3), instanced renderer (P1-T4).

## Tasks

### P2-T1 — Mechanism framework in the sim
- `parble-sim` mechanisms:
  - sensor volumes from sidecars
  - kinematic bodies for animated parts (flaps, trapdoors, hopper gate) with keyframed poses advanced by tick count
  - a `Mechanism` state machine trait with per-instance state saved in the track
  - named RNG sub-streams per mechanism instance (stable across edits elsewhere)
- An event stream (`MechanismEvent`, `ContactEvent` with impulse, `RollSample` per marble with speed and surface id) for audio and UI.
- Verify: unit tests for tick-based timing independent of frame rate, and determinism golden tests native and wasm stay green.
- Depends on: P1-T3.

### P2-T2 — Passive block pieces
- Generator additions: steep slope, mirrored curve, drop hole, redirect drop (internal tunnel exiting sideways one level lower), joiner (2 in, 1 out), support pillar, tower block with ports (`ref-06`).
- Verify: `make kit-check` and `make kit-determinism` pass. A sim test drops a marble through each piece and asserts the exit port and exit velocity range.
- Depends on: P1-T2.

### P2-T3 — Mechanism piece models
- Generator additions with separately named animated parts:
  - start hopper with release gate
  - finish collector cup
  - random splitter (flap)
  - L/R toggle (rocker)
  - checkpoint arch
  - one-way gate (hinged arch flap, `ref-10`/`ref-11`)
  - one-way hole (trapdoor)
- Animated part pivots are recorded in the sidecar.
- Verify: `make kit-check` passes, including animated part presence and pivot data.
- Depends on: P1-T2.

### P2-T4 — Rail family proof
- Rail generator: rail straight, rail 90° curve, S-rail 1×3, and a rail-to-block joint that plugs into block ports, using the same 28 mm channel. Matches `ref-05`/`ref-06`.
- Verify: `make kit-check` passes, and a sim test runs block → rail → S-rail → block with the seam bump metric under threshold.
- Depends on: P1-T2.

### P2-T5 — Mechanism behaviours and tests
- Implement each state machine:
  - hopper (queue, release one / all / interval)
  - finish (count, times)
  - splitter (seeded choice)
  - toggle (alternate on each pass)
  - checkpoint (split time, camera cue event)
  - one-way gate (opens only for travel in the allowed direction)
  - one-way hole (drops marbles arriving from the trap side, carries marbles from the other side over)
- Verify: one scripted sim test per mechanism, for example toggle sends 6 marbles L,R,L,R,L,R, the splitter matches the seeded sequence, reverse travel through the one-way pieces is blocked. Golden hashes are updated deliberately with a `PHYSICS_VERSION` bump.
- Depends on: P2-T1, P2-T3.

### P2-T6 — Render sync for mechanisms
- `parble-render` animates mechanism parts from sim state with interpolation between physics ticks.
- Verify: `shots-test` adds a toggle mid-flip shot and a one-way gate open shot.
- Depends on: P2-T5, P1-T4.

### P2-T7 — All-pieces test track
- `--scenario allpieces`: a track using all 16 PRD items, with 10 marbles released from the hopper.
- Verify:
  - All 10 reach the finish.
  - Identical trajectory hash native and wasm.
  - `make kit-check` passes over the full catalog.
  - The perf gate is still within budget.
- Depends on: P2-T2, P2-T4, P2-T5, P2-T6.

## Exit criteria
Every acceptance box under PRD §6 P2 checked with evidence.
